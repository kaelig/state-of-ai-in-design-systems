# Design systems supply the contract AG-UI lacks

AG-UI 1.0 can carry a design system's generative loop between an agent, Figma and code, but the design system has to bring the contract. The spec, released with its SDKs on 17 September 2026, defines how an application and an agent exchange a run: one `RunAgentInput` goes out, one ordered stream of typed events comes back, and nothing travels back mid-run ([DEPRECATIONS.md](https://github.com/ag-ui-protocol/ag-ui/blob/main/DEPRECATIONS.md); [Run Input](https://docs.ag-ui.com/spec/1.0/basic/run-input); [Interrupts and Resume](https://docs.ag-ui.com/spec/1.0/basic/patterns/interrupt-resume)). Its schema has no component, catalog or surface type, and the protocol validates none of the tool arguments it carries ([schema.json](https://ag-ui.com/spec/1.0/schema.json); [Tool Calls 1.0](https://docs.ag-ui.com/spec/1.0/events/tool-calls)). A team must supply the catalog and a validator for it, and bind each renderer to real components. A2UI already offers a catalog format that AG-UI middleware streams, but that middleware is at version 0.0.11 ([npm @ag-ui/a2ui-middleware](https://registry.npmjs.org/@ag-ui/a2ui-middleware)). A Figma plugin can host an AG-UI client in its UI iframe, and Storybook 10.6 can host an AG-UI endpoint and save a generated spec as a story, yet the research found no public project doing either ([How plugins run](https://developers.figma.com/docs/plugins/how-plugins-run/); [dev-server.ts](https://github.com/storybookjs/storybook/blob/v10.6.1/code/core/src/core-server/dev-server.ts); [GitHub code search](https://github.com/search?q=%22%40ag-ui%2Fclient%22+path%3A.storybook&type=code)). Southleft's Figma Console MCP fits the loop today as the agent's Figma tool backend. Nathan Curtis's Specs fits upstream, as the source of constraints that code metadata never records. Neither mentions AG-UI ([figma-console-mcp issues](https://github.com/southleft/figma-console-mcp/issues?q=ag-ui); [Specs docs](https://www.specsplugin.com/)). The State of AI in Design Systems corpus, a snapshot of 26–28 July 2026, has no record that mentions AG-UI, A2UI or CopilotKit, so a team that builds this builds the first public example ([State of AI in Design Systems](https://state-of-ai-in-design-systems.netlify.app)). Publish the catalog and its validator now, because every agent surface can use them. Build the Storybook client first and the Figma client second on the stable 1.0 core, and wait for the A2UI plumbing to reach 1.0 before depending on its key names.

## AG-UI 1.0 defines 31 events and no component

AG-UI is a request-and-stream protocol. The application "Owns the user. It renders the stream, executes the tool calls it advertised, keeps the state the agent shares with it, and decides what requires the user's consent" ([Architecture 1.0](https://docs.ag-ui.com/spec/1.0/architecture)). The agent receives exactly one `RunAgentInput` per run, carrying `threadId`, `runId`, `messages`, `state`, `tools`, `context`, `forwardedProps` and `resume` ([Run Input](https://docs.ag-ui.com/spec/1.0/basic/run-input)). It answers with a stream that opens with `RUN_STARTED` (or an immediate `RUN_ERROR`) and closes with `RUN_FINISHED` or `RUN_ERROR` ([Runs and Steps](https://docs.ag-ui.com/spec/1.0/events/lifecycle)). The schema defines 31 event types in eight families ([The Event Model](https://docs.ag-ui.com/spec/1.0/basic/index)). HTTP with Server-Sent Events is the one mandatory binding. Protobuf is optional, and WebSockets count as a custom transport outside the standard ([Transports](https://docs.ag-ui.com/spec/1.0/basic/transports/index)). "The protocol has no mid-run channel from the consumer" ([Interrupts and Resume](https://docs.ag-ui.com/spec/1.0/basic/patterns/interrupt-resume)). A designer's edit, a Figma selection or a renderer's validation error reaches the agent only at the next run boundary.

Rendering is out of scope by design. The spec "does not specify what any particular integration does with an event after receiving it … or how a UI should render anything" ([Specification 1.0](https://docs.ag-ui.com/spec/1.0/index)). The 98 definitions in the schema include no catalog, component or surface type ([schema.json](https://ag-ui.com/spec/1.0/schema.json)). A design system meets the protocol at five mechanisms instead.

| Design-system need | AG-UI 1.0 mechanism | What the protocol leaves to you |
|---|---|---|
| Offer the agent the component catalog | Frontend tools in `RunAgentInput.tools`, each with a JSON Schema `parameters` and optional `metadata` ([schema.json](https://ag-ui.com/spec/1.0/schema.json)) | Validating arguments, versioning schemas, fitting provider schema limits |
| Stream a UI tree a person can also edit | `STATE_SNAPSHOT` and `STATE_DELTA`, an RFC 6902 JSON Patch ([State 1.0](https://docs.ag-ui.com/spec/1.0/events/state)) | Merging concurrent edits; edits made mid-run wait for the next run |
| Show a rendered surface in the conversation | `ACTIVITY_SNAPSHOT` and `ACTIVITY_DELTA` with an open `activityType` ([Activity 1.0](https://docs.ag-ui.com/spec/1.0/events/activity)) | The surface format; activity content never returns to the agent |
| Hold output for design review | `RUN_FINISHED` with an interrupt outcome, answered by `resume` entries ([Interrupts and Resume](https://docs.ag-ui.com/spec/1.0/basic/patterns/interrupt-resume)) | The review UI and any diff |
| Pass guidelines and rules | `context` entries, each a description and a string value ([schema.json](https://ag-ui.com/spec/1.0/schema.json)) | Any guarantee the model obeys them |

Frontend tools are the most direct route for a catalog. The agent streams a call to an advertised tool and "MUST NOT answer it". The run finishes as success with the call listed in `pendingToolCallIds`, and the application executes the call and returns a tool message in the next run ([Tool Calls 1.0](https://docs.ag-ui.com/spec/1.0/events/tool-calls)). The protocol carries `parameters` "opaquely" and "does not constrain or validate it" ([schema.json](https://ag-ui.com/spec/1.0/schema.json)). Arguments "MUST be treated as untrusted input" and validated against the declared schema ([Tool Calls 1.0](https://docs.ag-ui.com/spec/1.0/events/tool-calls)). CopilotKit already ships this pattern as Components as Tools: `useComponent` exposes a React component to the agent and passes the tool's arguments "straight through as typed props" ([CopilotKit Components as Tools](https://docs.copilotkit.ai/generative-ui/tool-based)). `Tool.metadata` is the sanctioned slot for "rendering or routing information" ([schema.json](https://ag-ui.com/spec/1.0/schema.json)). That makes it the place for a catalog version or a Figma component key.

The spec's rules for unanswered calls already describe a validate-and-repair cycle. Every pending call must be answered before the thread continues, and "a failure is still an answer, as a tool message with `error` set" ([Tool Calls 1.0](https://docs.ag-ui.com/spec/1.0/events/tool-calls)). A renderer that rejects a component tree can say why in that error, and the agent reads it on the next run. The same page says "A consumer MUST NOT act on the arguments before `TOOL_CALL_END`" and that "closing establishes completeness, not validity" ([Tool Calls 1.0](https://docs.ag-ui.com/spec/1.0/events/tool-calls)). The client SDK hands subscribers partially parsed arguments as they stream ([AgentSubscriber](https://docs.ag-ui.com/sdk/js/client/subscriber)). This report reads the two together: a renderer can preview partial arguments, but writing Figma nodes or saving a story waits for the end event and a passing validation.

State and activity differ in one way that decides where a UI tree lives. State persists across runs, and "the next run's input carries it back as the starting value" ([State 1.0](https://docs.ag-ui.com/spec/1.0/events/state)). Activity messages "never travel back to the producer: a consumer MUST strip them from `messages` before sending" ([Run Input](https://docs.ag-ui.com/spec/1.0/basic/run-input)). A tree that a designer adjusts between turns belongs in state, where the agent sees the adjusted version. A render-only surface can live in activity. Either way, "State events are remote writes into application state", and an application "MUST validate what it reads out of state before acting on it" ([State 1.0](https://docs.ag-ui.com/spec/1.0/events/state)). A patch that fails must not be kept half-applied ([Snapshots and Deltas](https://docs.ag-ui.com/spec/1.0/basic/patterns/snapshots)). The protocol offers replace and patch, nothing more, so concurrent designer and agent edits need a rule the application defines.

Interrupts are the review gate. A run can end with an interrupt outcome that lists interrupts, each with an optional `responseSchema` "carried opaquely so a consumer can build a form for it". The next input must answer every one of them in `resume` ([Interrupts and Resume](https://docs.ag-ui.com/spec/1.0/basic/patterns/interrupt-resume)). The concept docs describe an approve-with-edits pattern whose `editedArgs` "is a full replacement, not a partial merge" ([Interrupts concept](https://docs.ag-ui.com/concepts/interrupts)). The spec keeps interrupts apart from frontend tools. An interrupt is the producer "explicitly stopping to ask", while a frontend tool call "rides the ordinary message loop" ([Tool Calls 1.0](https://docs.ag-ui.com/spec/1.0/events/tool-calls)).

Some gaps matter to a design system. Capability retrieval is unspecified: "No transport binding in this version carries a capabilities exchange" ([Capabilities 1.0](https://docs.ag-ui.com/spec/1.0/basic/capabilities)). A `context` value is a string, so a catalog sent as context is prompt material with no protocol guarantee behind it ([schema.json](https://ag-ui.com/spec/1.0/schema.json)). Streaming tool arguments into state before the tool finishes, called predictive state, is a LangGraph and CopilotKit convention carried in a `CUSTOM` event named `PredictState`, not part of 1.0 ([state_streaming.py](https://github.com/ag-ui-protocol/ag-ui/blob/main/integrations/langgraph/python/ag_ui_langgraph/middlewares/state_streaming.py); [convert.ts](https://github.com/ag-ui-protocol/ag-ui/blob/main/sdks/typescript/packages/client/src/legacy/convert.ts)). AG-UI's own generative UI draft warns that "OpenAI enforces a limit of 1024 characters for tool descriptions" and that "Classes, nesting, `$ref`, and `oneOf` are not reliably supported across LLM providers" ([Generative UI draft](https://docs.ag-ui.com/drafts/generative-ui)). Prop schemas with discriminated unions will need flattening before a model sees them.

The core is stable enough to build on, and its governance is thin. The first-party SDKs are TypeScript, Python and .NET ([Specification 1.0](https://docs.ag-ui.com/spec/1.0/index)). `@ag-ui/core` recorded 2,535,905 downloads in the week to 28 September 2026 ([npm downloads](https://api.npmjs.org/downloads/point/last-week/@ag-ui/core)). Integrations cover LangGraph, CrewAI, Microsoft Agent Framework, Google ADK, AWS Strands, Mastra, Pydantic AI and the Claude Agent SDK, among others ([AG-UI Overview](https://docs.ag-ui.com/introduction)). Retired 0.x shapes stay shimmed until 17 September 2027 ([DEPRECATIONS.md](https://github.com/ag-ui-protocol/ag-ui/blob/main/DEPRECATIONS.md)), and "A 0.x agent keeps working against a 1.0 client" ([Migrating to 1.0](https://docs.ag-ui.com/migrating-to-1-0)). CopilotKit stewards the project and sells optional support ([Production support](https://docs.ag-ui.com/talk-to-us)). The repository is MIT-licensed and has no governance file ([LICENSE](https://github.com/ag-ui-protocol/ag-ui/blob/main/LICENSE); [CONTRIBUTING.md](https://github.com/ag-ui-protocol/ag-ui/blob/main/CONTRIBUTING.md)). The Linux Foundation's Agentic AI Foundation does not list it ([AAIF Projects](https://aaif.io/projects/)). A secondary source reports that CopilotKit raised a $27 million Series A in May 2026 ([Pulse 2.0](https://pulse2.com/copilotkit-27-million-series-a-raised-for-enterprise-agentic-frontend-stack/)).

## A2UI supplies the catalog, on 0.0.11 middleware

AG-UI's docs say "AG-UI is not a generative UI specification" and that it "natively supports" A2UI, MCP-UI and Open-JSON-UI ([Generative UI specs](https://docs.ag-ui.com/concepts/generative-ui-specs)). CopilotKit sorts generative UI into three lanes. In the Controlled lane "you wrote the component; the agent only picks *which* one". In the Declarative lane the agent emits a spec and the frontend composes it "from a catalog you registered". In the Open-Ended lane an MCP server invents the UI in a sandbox, "hardest to guarantee accessibility / brand / security" ([CopilotKit Generative UI overview](https://docs.copilotkit.ai/concepts/generative-ui-overview)). A design system wants the first two lanes. MCP Apps, the open-ended lane, can render anything, so it cannot promise approved components.

A2UI treats the catalog as a versioned API. A catalog is "a JSON Schema file that defines the UI components, functions, and themes an agent can use", identified by a `catalogId` ([A2UI Catalogs](https://a2ui.org/concepts/catalogs/)). The client lists `supportedCatalogIds` in order of preference, the agent picks one at `createSurface`, and the choice "is locked for the lifetime of that surface". Catalogs are known at deploy time, and inline catalogs are "supported but not recommended in production" ([A2UI Catalogs](https://a2ui.org/concepts/catalogs/)). The versioning rules read like a design system's deprecation policy: add only, mark removals `deprecated: true`, and put breaking changes under a new versioned `catalogId` URI ([A2UI Catalogs](https://a2ui.org/concepts/catalogs/)). A client that rejects generated UI returns `VALIDATION_FAILED` with the `surfaceId`, a JSON Pointer `path` and a message, so the agent can correct itself ([A2UI v0.9.1 specification](https://a2ui.org/specification/v0.9.1-a2ui/)). The docs tell teams to "Define a catalog that mirrors your existing design system" ([A2UI Catalogs](https://a2ui.org/concepts/catalogs/)). Google's v0.9 announcement said it more bluntly: "Frontend developers don't want new components. They already have a design system." The same post lists React, Lit, Angular and Flutter renderers ([A2UI v0.9 announcement](https://developers.googleblog.com/a2ui-v0-9-generative-ui/)). A multi-platform design system gets one catalog and a renderer per platform.

AG-UI carries A2UI through a first-party middleware. `@ag-ui/a2ui-middleware` 0.0.11, published 30 September 2026, emits `ACTIVITY_SNAPSHOT` events with `activityType: "a2ui-surface"` and `content: { a2ui_operations: [...] }`, plus status values `building`, `retrying` and `failed` ([a2ui-middleware source](https://github.com/ag-ui-protocol/ag-ui/blob/main/middlewares/a2ui-middleware/src/index.ts); [npm @ag-ui/a2ui-middleware](https://registry.npmjs.org/@ag-ui/a2ui-middleware)). It can inject a `render_a2ui` tool. It puts the catalog into `context` as `JSON.stringify({ catalogId, components })`, validates with up to three attempts, and reads user actions from `forwardedProps.a2uiAction.userAction` ([a2ui-middleware source](https://github.com/ag-ui-protocol/ag-ui/blob/main/middlewares/a2ui-middleware/src/index.ts)). Its types state that "catalog choice belongs to the host/factory, not the subagent" ([types.ts](https://github.com/ag-ui-protocol/ag-ui/blob/main/middlewares/a2ui-middleware/src/types.ts)). CopilotKit turns it on with `a2ui: {}` on the runtime ([CopilotKit A2UI](https://docs.copilotkit.ai/generative-ui/a2ui)). Its `createCatalog` keeps "platform-agnostic (Zod schemas + descriptions)" definitions apart from React renderers, so the renderer can be the design system's own component ([a2ui-renderer SKILL.md](https://cdn.jsdelivr.net/npm/@copilotkit/a2ui-renderer@1.61.2/skills/a2ui-renderer/SKILL.md)). AG2 emits the same `a2ui-surface` activity and adds "optional schema validation with automatic retry" ([AG2 docs](https://docs.ag2.ai/latest/docs/user-guide/ag-ui/a2ui)).

The research notes disagree on A2UI's exact shapes, and the newer sources win. The AG-UI research read the v0.9 spec page, created 20 November 2025 ([A2UI v0.9 specification](https://a2ui.org/specification/v0.9-a2ui/)). The landscape research read v0.9.1 and the a2ui.org home page on 29–30 September 2026. Those call v0.9.1 production-ready and describe a v1.0 candidate that adds an `actionResponse` message and renames `theme` to `surfaceProperties` ([a2ui.org](https://a2ui.org/)). Both versions share the four server-to-client messages, `createSurface`, `updateComponents`, `updateDataModel` and `deleteSurface` ([A2UI v0.9.1 specification](https://a2ui.org/specification/v0.9.1-a2ui/)). The AG-UI wire departs from the A2UI spec in three places. The middleware wraps A2UI messages in its own `a2ui_operations` envelope. It takes user actions through `forwardedProps` rather than an A2UI `action` message. It ships the catalog inline at runtime, which A2UI does not recommend for production ([a2ui-middleware source](https://github.com/ag-ui-protocol/ag-ui/blob/main/middlewares/a2ui-middleware/src/index.ts); [A2UI Catalogs](https://a2ui.org/concepts/catalogs/)). Even the context marker differs. The middleware labels the catalog "A2UI Component Schema — available components for generating UI surfaces…", while a 1 May 2026 post on CopilotKit's Angular integration describes the marker "A2UI Custom Catalog" ([a2ui-middleware source](https://github.com/ag-ui-protocol/ag-ui/blob/main/middlewares/a2ui-middleware/src/index.ts); [Angular Architects](https://www.angulararchitects.io/en/blog/custom-catalogs-in-a2ui-your-own-components-for-ai-generated-uis/)). The middleware is the newer source. All of these names live in a 0.0.x package whose latest changelog entry "Documented the parallel call limitation" ([a2ui-middleware CHANGELOG](https://github.com/ag-ui-protocol/ag-ui/blob/main/middlewares/a2ui-middleware/CHANGELOG.md)). Adopt A2UI's catalog model. Do not hard-code the middleware's key names yet.

Other declarative formats have catalogs but lack A2UI's negotiation and error path. json-render declares catalogs with Zod and streams JSONL patches to many renderers ([json-render catalog](https://json-render.dev/docs/catalog); [json-render repository](https://github.com/vercel-labs/json-render)). Tambo registers components with a Zod `propsSchema` and supports React only ([Tambo docs](https://docs.tambo.co/)). OpenUI Lang "validates output and drops invalid portions" ([OpenUI Lang](https://www.openui.com/docs/openui-lang)). Open-JSON-UI appears only on AG-UI and CopilotKit pages, and the research found no OpenAI-hosted spec for it ([Generative UI specs](https://docs.ag-ui.com/concepts/generative-ui-specs); [CopilotKit generative-ui](https://github.com/CopilotKit/generative-ui)).

Design system teams have not taken any of this up in public. The corpus, a snapshot of 26–28 July 2026, returns zero hits for A2UI, AG-UI, CopilotKit, json-render and "generative UI", and its further-reading list has no entry on them ([State of AI in Design Systems](https://state-of-ai-in-design-systems.netlify.app); [Further reading](https://state-of-ai-in-design-systems.netlify.app/reading)). The research found two community projects with about one star each. `agui-cloudscape-renderer` bridges A2UI to the AWS Cloudscape design system ([agui-cloudscape-renderer](https://github.com/golevishal/agui-cloudscape-renderer)). `dspack-studio` "builds the interface from your design system's *approved components only*, checks every attempt against the system's own rules, repairs what it can", generating A2UI streamed over AG-UI ([dspack-studio](https://github.com/aestheticfunction/dspack-studio)). That second project is the closest public sketch of the whole idea.

## A Figma plugin can host an AG-UI client; nobody has shipped one

Figma's plugin runtime permits it. Plugin code runs in a main-thread sandbox that "does not expose browser APIs". A plugin reaches browser APIs by opening an iframe with `figma.showUI()`, and the two sides talk by message passing ([How plugins run](https://developers.figma.com/docs/plugins/how-plugins-run/)). The iframe has a `null` origin, so it can call only APIs that send `Access-Control-Allow-Origin: *` ([Making network requests](https://developers.figma.com/docs/plugins/making-network-requests/)). The manifest's `networkAccess` permits `http`, `https`, `ws` and `wss`, allows localhost with a stated reason, and shows the domain list on the plugin's Community page ([Plugin manifest](https://developers.figma.com/docs/plugins/manifest/)). An AG-UI `HttpAgent` that posts a run and reads SSE can therefore live in the iframe and relay decoded events to the main thread, which calls the Plugin API. Southleft's Desktop Bridge plugin already runs this shape with WebSockets: networking in `ui.html`, a `postMessage` relay, and a command executor on the main thread ([manifest.json](https://github.com/southleft/figma-console-mcp/blob/db1967f479514710acc64be4c527ac033410b772/figma-desktop-bridge/manifest.json); [ui.html](https://github.com/southleft/figma-console-mcp/blob/db1967f479514710acc64be4c527ac033410b772/figma-desktop-bridge/ui.html)).

Figma's own docs disagree about `fetch` in the sandbox. "How plugins run" says `fetch` is "not directly available from the sandbox", while the "Global objects" reference lists a global `fetch` that returns a `FetchResponse` ([How plugins run](https://developers.figma.com/docs/plugins/how-plugins-run/); [Global objects](https://developers.figma.com/docs/plugins/api/global-objects)). The research could not date either page, so neither can be called newer. Neither page documents a streaming response body. Keep the SSE client in the iframe.

Figma's official MCP server is the wrong base for an event-driven loop today. It now writes as well as reads, with `use_figma` as the "General-purpose tool for writing to Figma files", and its tools page listed 29 tools on 30 September 2026 ([Figma MCP tools and prompts](https://developers.figma.com/docs/figma-mcp-server/tools-and-prompts/)). "Only MCP clients listed in the Figma MCP Catalog can connect", and the docs describe no events or subscriptions ([Figma MCP server](https://developers.figma.com/docs/figma-mcp-server/)). The corpus, a snapshot of 26–28 July 2026, records rate limits that run from 6 calls a month on View and Collab seats to 200–600 a day on Dev and Full seats, and Code Connect limited to Organization and Enterprise plans ([Figma MCP rate limits](https://developers.figma.com/docs/figma-mcp-server/rate-limits-access/); [Code Connect React](https://developers.figma.com/docs/code-connect/react/)). A custom AG-UI agent reaches Figma more easily through an open-source bridge.

AG-UI gives a Figma-to-code loop its session plumbing and nothing about design. It supplies threads, streamed tool calls, JSON Patch state, interrupts and subagents ([State 1.0](https://docs.ag-ui.com/spec/1.0/events/state); [Key Changes](https://docs.ag-ui.com/spec/1.0/changelog)). It has no notion of a component's identity across Figma and code. Code Connect maps Figma properties to code props, for example `figma.enum('Type', {Primary:'primary', …})` ([Code Connect React](https://developers.figma.com/docs/code-connect/react/)). Going back to the canvas is weak everywhere. Layers copied out of Figma Make "aren't connected to the Figma Make file" and are "not automatically tied to your design system" ([Figma Help: Copy a Make preview](https://help.figma.com/hc/en-us/articles/35060759685015-Copy-a-Figma-Make-preview-as-design-layers)). Anima goes from Figma to code only. Among the tools the research surveyed, none turns a generated A2UI or json-render surface into Figma library instances ([Anima](https://animaapp.com/blog/design-systems/vibe-code-with-your-figma-design-system/); [Figma Help: Copy a Make preview](https://help.figma.com/hc/en-us/articles/35060759685015-Copy-a-Figma-Make-preview-as-design-layers)).

### Figma Console MCP works today as the agent's Figma backend

Figma Console MCP 1.40.7 is a Node MCP server on stdio that also runs a local HTTP and WebSocket server on ports 9223–9232 ([README](https://github.com/southleft/figma-console-mcp/blob/db1967f479514710acc64be4c527ac033410b772/README.md); [architecture.md](https://github.com/southleft/figma-console-mcp/blob/db1967f479514710acc64be4c527ac033410b772/docs/architecture.md)). The Desktop Bridge plugin, imported as a development plugin, dials into that server from its UI iframe. It relays commands to the main thread, which handles 74 command types ([architecture.md](https://github.com/southleft/figma-console-mcp/blob/db1967f479514710acc64be4c527ac033410b772/docs/architecture.md); [code.js](https://github.com/southleft/figma-console-mcp/blob/db1967f479514710acc64be4c527ac033410b772/figma-desktop-bridge/code.js)). A Cloudflare Worker variant reaches the same plugin through a Durable Object relay after a six-character pairing ([architecture.md](https://github.com/southleft/figma-console-mcp/blob/db1967f479514710acc64be4c527ac033410b772/docs/architecture.md)). The earlier Chrome DevTools Protocol path broke when Figma blocked `--remote-debugging-port` in February 2026, and v1.26.0 removed it on 16 May 2026 ([CHANGELOG](https://github.com/southleft/figma-console-mcp/blob/db1967f479514710acc64be4c527ac033410b772/CHANGELOG.md)). The source registers 126 tool names, 121 of them in Local Mode. About 70 write to the document, and `figma_execute` runs arbitrary Plugin API JavaScript ([tools.md](https://github.com/southleft/figma-console-mcp/blob/db1967f479514710acc64be4c527ac033410b772/docs/tools.md); [local.ts](https://github.com/southleft/figma-console-mcp/blob/db1967f479514710acc64be4c527ac033410b772/src/local.ts)). Uber's uSpec pairs a Cursor agent with it to write design specs: "The agent doesn't guess at property names—it selects from documented APIs" ([Uber: automate design specs](https://www.uber.com/blog/automate-design-specs/)). The corpus, a snapshot of 26–28 July 2026, has no record of Figma Console MCP, Southleft, Specs or Nathan Curtis ([State of AI in Design Systems](https://state-of-ai-in-design-systems.netlify.app)).

Its events stop at the server. The plugin pushes selection, document, page and console events over the WebSocket, and the server re-emits them as Node events ([code.js events](https://github.com/southleft/figma-console-mcp/blob/db1967f479514710acc64be4c527ac033410b772/figma-desktop-bridge/code.js#L7223-L7350); [websocket-server.ts](https://github.com/southleft/figma-console-mcp/blob/db1967f479514710acc64be4c527ac033410b772/src/core/websocket-server.ts#L490-L590)). The server buffers them for pull tools such as `figma_get_design_changes`, and the code sends no MCP notifications ([local.ts](https://github.com/southleft/figma-console-mcp/blob/db1967f479514710acc64be4c527ac033410b772/src/local.ts#L1631); [src](https://github.com/southleft/figma-console-mcp/tree/db1967f479514710acc64be4c527ac033410b772/src)). A document-change event carries up to 50 changed node IDs and a count. It carries no property values and no field that says whether a designer or an agent made the change ([code.js events](https://github.com/southleft/figma-console-mcp/blob/db1967f479514710acc64be4c527ac033410b772/figma-desktop-bridge/code.js#L7223-L7350)). Cloud Mode has no real-time monitoring at all ([README](https://github.com/southleft/figma-console-mcp/blob/db1967f479514710acc64be4c527ac033410b772/README.md)).

Three integration paths follow from that architecture, ordered by how much new code each needs ([architecture.md](https://github.com/southleft/figma-console-mcp/blob/db1967f479514710acc64be4c527ac033410b772/docs/architecture.md); [tools.md](https://github.com/southleft/figma-console-mcp/blob/db1967f479514710acc64be4c527ac033410b772/docs/tools.md); [websocket-server.ts](https://github.com/southleft/figma-console-mcp/blob/db1967f479514710acc64be4c527ac033410b772/src/core/websocket-server.ts#L805); [Runs and Steps](https://docs.ag-ui.com/spec/1.0/events/lifecycle)).

| Path | What it reuses | What is missing | Verdict |
|---|---|---|---|
| An AG-UI agent calls Figma Console MCP as its tool backend and streams AG-UI to a separate frontend | Every local tool, unchanged; the agent framework turns MCP calls into `TOOL_CALL_*` events | Push, so the agent polls between turns; summarizing large payloads into state; telling designer edits from agent edits | Uses only existing pieces; no public build pairs it with AG-UI yet |
| A fork of the Desktop Bridge becomes an AG-UI client that renders a UI tree as component instances | The iframe networking pattern; the instance, property, slot and variable handlers in `code.js` | An SSE client; a map from catalog entries to Figma component keys; a JSON Patch applier with a keyed reconciler; batching under the 5-second and 15-second command timeouts; distribution beyond a development import | Feasible, and the most novel path |
| Figma Console MCP exposes its own AG-UI endpoint | The Node event emitter and the HTTP listener that serves `/health` | An agent loop, since AG-UI describes agent runs and Console MCP has none | A category mismatch |

The second path inverts Figma Console MCP's topology. Today the Node server commands the plugin. As an AG-UI client, the plugin would advertise handlers such as instantiate a component, set instance properties, fill a slot and capture a screenshot as frontend tools, and the agent would call them through `TOOL_CALL_*` events ([tools.md](https://github.com/southleft/figma-console-mcp/blob/db1967f479514710acc64be4c527ac033410b772/docs/tools.md); [Tool Calls 1.0](https://docs.ag-ui.com/spec/1.0/events/tool-calls)). The spec says applications "SHOULD obtain user consent before executing a side-effectful tool call" ([Tool Calls 1.0](https://docs.ag-ui.com/spec/1.0/events/tool-calls)), which gives every canvas write a natural approval step.

A shorter route exists for dashboards. Figma Console MCP ships two experimental MCP Apps, a token browser and a design-system audit dashboard, behind `ENABLE_MCP_APPS=true` ([README](https://github.com/southleft/figma-console-mcp/blob/db1967f479514710acc64be4c527ac033410b772/README.md)). CopilotKit's `MCPAppsMiddleware` renders MCP Apps inside AG-UI frontends ([CopilotKit MCP Apps](https://docs.showcase.copilotkit.ai/generative-ui/mcp-apps)). Nobody has tested the pairing, and the research did not confirm that the cloud server registers the app tools.

Southleft has built each half of the loop without joining them. TJ Pitre's January 2026 article describes A2UI output as "a recipe: a structured JSON description of what UI elements should appear", with an A2UI Bridge renderer for Mantine and ShadCN ([Southleft: A2UI](https://southleft.com/insights/ai/a2ui-how-ai-agents-build-real-user-interfaces)). A September 2026 demo runs a 2B-parameter in-browser model against an 18-component design system speaking A2UI v0.9. Its deterministic guardrail layer handles output that fails `JSON.parse` "53 times out of 65" ([local-generative-ui-demo](https://github.com/southleft/local-generative-ui-demo/blob/caf16801aa2e8f918936e21c8cd7771d856492ce/README.md)). `ds-contracts-poc` connects React and Figma through "a shared, machine-readable contract", and an agent holding the Figma Console MCP tools performs its canvas writes ([ds-contracts-poc](https://github.com/southleft/ds-contracts-poc/blob/4df13f6726c933c94b04a7118fe27215c69e9910/README.md); [first-pass-run.ts](https://github.com/southleft/ds-contracts-poc/blob/4df13f6726c933c94b04a7118fe27215c69e9910/extract/figma/census/first-pass-run.ts)). A search of five Southleft repositories for `ag-ui` and `copilotkit` returned no files ([figma-console-mcp](https://github.com/southleft/figma-console-mcp/tree/db1967f479514710acc64be4c527ac033410b772); [story-ui](https://github.com/southleft/story-ui/tree/f960dda85257854c20fe13acc1e36c1ae3bf50de)).

## Specs records constraints that code metadata never does

"Specs" names two Figma plugins. Specs 2, first published in 2025 as "Anova", is current, and its Community listing had 2,997 users when fetched. Specs Classic, launched in February 2023, now reads "SPECS CLASSIC IS DEPRECATED. USE SPECS 2" and had 139,352 users ([Figma Community search API](https://www.figma.com/api/search/resources?query=nathan%20curtis&resource_type=plugin&sort=relevancy&price=all&creators=all); [Specs Licensing](https://www.specsplugin.com/overview/licensing/); [EightShapes article](http://web.archive.org/web/20250823100333/https://medium.com/eightshapes-llc/the-eightshapes-specs-figma-plugin-2892f21adc96)). Both come from Nathan Curtis's company, Directed Edges. Everything works on the free tier, and Pro costs $10 a month ([Specs Licensing](https://www.specsplugin.com/overview/licensing/)).

Specs 2 computes a component's contract from the file. One click produces six on-canvas sections, and the Data section holds "The same spec as structured YAML or JSON — a ready-made contract for AI/LLM tools" ([Specs 2 plugin](https://www.specsplugin.com/plugin/)). The engine "reads Figma components and produces complete, machine-readable specifications in YAML or JSON", and the CLI and plugin "produce identical output from the same input" ([About Specs](https://www.specsplugin.com/overview/aboutspecs/)). A spec records named anatomy elements, props with closed enums and defaults, and a default variant whose styles bind to DTCG-style token references. It also records variants as layered deltas, invalid prop combinations, subcomponents and examples ([Schema overview](https://www.specsplugin.com/schema/); [TokenReference](https://www.specsplugin.com/schema/token-reference/)). Slot props carry `anyOf`, meaning "Permitted component type names", with `minChildren` and `maxChildren` ([Schema: Props](https://www.specsplugin.com/schema/props/)). Roles such as `button` or `togglebutton` come from designers' Dev Mode annotations and are off unless enabled, and `dismiss` is the only documented action ([Roles](https://www.specsplugin.com/roles/); [Actions](https://www.specsplugin.com/actions/)). Curtis's Button example shrinks from 1.38 MB of raw Figma data to 10 KB of spec ([Figma Component Specs on Command](https://nathanacurtis.substack.com/p/figma-component-specs-on-command)).

A spec is machine-readable, but it is not a tool schema. It is an instance document that validates against the Specs JSON Schema, a draft-07 schema published in `@directededges/specs-schema` 0.34.0 under CC BY 4.0 ([npm: specs-schema](https://registry.npmjs.org/@directededges%2Fspecs-schema); [component.schema.json](https://unpkg.com/@directededges/specs-schema@0.34.0/schema/component.schema.json)). It does not express a component's props as JSON Schema. To use a spec as AG-UI tool `parameters` or as an A2UI catalog entry, a team writes a transform: enums become `enum`, slot rules become array constraints, and invalid combinations become `not` clauses. Specs ships no such transform. Its code transforms emit a TypeScript `contract.ts`, React and Lit scaffolds, CSS and Storybook stories, and `invalidPropCombinations` becomes "nothing. Not a prop. It constrains which combinations the stories emit" ([Code: What gets emitted](https://www.specsplugin.com/code/); [Code: Contract](https://www.specsplugin.com/code/contract/)).

Three limits apply. Token references, prop bindings, invalid combinations and examples are Pro-only, so a free spec constrains an agent less than the schema suggests ([Specs Licensing](https://www.specsplugin.com/overview/licensing/); [CLI Overview](https://www.specsplugin.com/cli/)). The schema shipped 18 npm versions between 6 April and 23 September 2026, and 0.34.0 renamed `invalidVariantCombinations` to `invalidPropCombinations` ([npm: specs-schema](https://registry.npmjs.org/@directededges%2Fspecs-schema); [Releases](https://www.specsplugin.com/overview/releases/)). The Figma-to-spec engine, `@directededges/specs-from-figma`, carries the PolyForm Internal Use license, so generating specs depends on Directed Edges' closed engine ([npm: specs-from-figma](https://registry.npmjs.org/@directededges%2Fspecs-from-figma)). The docs also disagree about an MCP server. The Terms of Service call the CLI "A command-line interface and MCP server for design system operations", and the 0.1.0 release note of 10 February 2026 says the same ([Terms of Service](https://www.specsplugin.com/overview/terms-of-service/); [Releases](https://www.specsplugin.com/overview/releases/)). The newer 0.31.0 package has no MCP dependency, its bundle contains no "mcp" string, and the current command list has no MCP command ([npm: specs-cli](https://registry.npmjs.org/@directededges%2Fspecs-cli); [CLI Overview](https://www.specsplugin.com/cli/)). Treat Specs as having no MCP server today.

Curtis's own writing sets Specs' place in an agent loop. "AI belongs in this pipeline: *downstream*, not necessarily to generate specs," he writes, and "AI should be reading, not writing, these specs from Figma" ([Figma Component Specs on Command](https://nathanacurtis.substack.com/p/figma-component-specs-on-command)). "A description informs. A contract arbitrates" ([Component Contracts and Schemas](https://nathanacurtis.substack.com/p/component-contracts-and-schemas)). He expects scripts to "generate 80-90% of the code you need before agents get to work" ([Component Contracts and Schemas](https://nathanacurtis.substack.com/p/component-contracts-and-schemas)). He assigns "how to use" knowledge to coded implementations, not to specs ([Spec-Driven UI Component Development](https://nathanacurtis.substack.com/p/spec-driven-ui-component-development)). None of his posts or the Specs docs pages the research searched mention AG-UI, A2UI or generative UI ([Substack archive](https://nathanacurtis.substack.com/api/v1/archive?sort=new&limit=50); [specsplugin.com](https://www.specsplugin.com/)).

So Specs belongs upstream of an AG-UI loop, at build time, tightening a catalog built from code. Code metadata knows import paths, runtime prop types, events and usage snippets ([Storybook Manifests](https://storybook.js.org/docs/ai/manifests.md); [Custom Elements Manifest schema](https://raw.githubusercontent.com/webcomponents/custom-elements-manifest/main/schema.d.ts); [Code Connect React](https://developers.figma.com/docs/code-connect/react/)). Specs knows the design intent that code leaves implicit ([Schema overview](https://www.specsplugin.com/schema/); [Schema: Props](https://www.specsplugin.com/schema/props/); [Specs Licensing](https://www.specsplugin.com/overview/licensing/)).

| What an agent needs | Specs 2 | Storybook manifest | Code Connect |
|---|---|---|---|
| Import path | No | Yes | Yes |
| Prop types and defaults | Yes, from Figma, with closed enums | Yes, from TypeScript | Mapped props only |
| Invalid prop combinations | Yes (Pro) | No | No |
| Slot allow-list and child count | Yes, when conventions declare it | No | No |
| Roles | If designers annotate them | No | No |
| Token reference per variant | Yes (Pro) | No | No |
| Usage snippets | Examples (Pro) | Yes | Yes |
| Figma node identity | Yes | No | Yes, by URL |
| Format stability | Pre-1.0, 18 versions in six months | "not yet stable" | Stable API |

The provider limits above suggest splitting the catalog in two. The Specs JSON Schema models props as a `oneOf` over six kinds ([component.schema.json](https://unpkg.com/@directededges/specs-schema@0.34.0/schema/component.schema.json)), and invalid combinations need `not` clauses. AG-UI's draft says providers support `oneOf` and `$ref` unevenly ([Generative UI draft](https://docs.ag-ui.com/drafts/generative-ui)). Give the model a flat schema of component names, enums and defaults. Put Specs' stricter rules in the client validator, which returns path-level errors the agent can fix. Specs also records Figma identities: `metadata.source` node IDs and variable IDs under `$extensions.com.figma` ([Schema: Metadata](https://www.specsplugin.com/schema/metadata/); [TokenReference](https://www.specsplugin.com/schema/token-reference/)). That is half of the catalog-to-Figma map the plugin path needs, and Code Connect or the Storybook manifest supplies the code half.

Adopting AG-UI makes little sense for the Specs engine itself. It processes locally and transmits no design data ([Terms of Service](https://www.specsplugin.com/overview/terms-of-service/)), and it has no agent loop of its own. Two edges can join a loop. The Specs 2 plugin already talks to the CLI through a local bridge, and the CLI's `render` command "sends specs into the live file through it" ([CLI: bridge](https://www.specsplugin.com/cli/commands/bridge/)). That bridge is a candidate export path for spec-shaped output into Figma. A plugin that hosted an AG-UI client can also offer "spec the selected component" as a frontend tool. Both ideas are this report's inference; nothing in Directed Edges' docs signals either.

## Every prototyping environment generates code and checks it afterward

The environments teams use today write free-form code against a real package plus prose rules, then test adherence. Figma Make kits "combine design system components with detailed guidelines" drawn from an npm package ([Figma blog: Make kits](https://www.figma.com/blog/introducing-make-kits-and-make-attachments/)). The corpus, a snapshot of 26–28 July 2026, found no public case study of a Make kit at a named enterprise design system ([Figma: write design system guidelines](https://developers.figma.com/docs/code/write-design-system-guidelines/)). v0's Design Systems 2.0 extracts components, props and tokens from a package or repository and tells the model: "If a component, prop, or token cannot be verified from the sources, v0 should not use it" ([v0 Design Systems 2.0](https://v0.app/docs/design-systems-2)). Lovable stores "tokens, component catalog, constraints" in `.lovable/design-system.json`, flags "raw color literals", and supports React only ([Lovable design systems](https://docs.lovable.dev/features/design-systems)). Bolt, UXPin Forge and Builder.io Fusion follow the same pattern ([Bolt](https://support.bolt.new/building/design-system/introduction); [UXPin Forge](https://www.uxpin.com/forge); [Builder.io](https://www.builder.io/c/docs/fusion-design-system-intelligence)). None of them constrains the output format, so the promise that only approved components appear is probabilistic.

First-party numbers show what that costs. Atlassian reported in November 2025 that its prototyping setup reached "70% Atlassian Design System accuracy in one pass". Its early failures were "Incorrect component imports, wrong token names, icons that seem on-brand but don't exist", and it concluded that "Structured configuration beats open-ended prompting" ([Atlassian: handoffs into handshakes](https://www.atlassian.com/blog/design/turning-handoffs-into-handshakes-integrating-design-systems-for-ai-prototyping-at-scale)). Its June 2026 test found that DESIGN.md "required ~92% more tokens", had "~2.7x the variance", and "was more likely to re-create components rather than use the existing system" ([Atlassian: DESIGN.md](https://www.atlassian.com/blog/how-we-build/atlassians-design-md-is-here-what-we-learned-testing-portable-design-context-in-practice)). Uber's Base MCP serves 500+ users and has handled 50,000+ tool calls, and Uber warns that "Stale design system data fails quietly" ([Uber Base MCP](https://uber.design/base-mcp)). Vercel's `design.md` cut failures from 91 to 39 across six pages, yet every page still carried a ship-blocking failure ([Vercel: design.md](https://vercel.com/blog/how-our-agents-build-on-brand-pages-with-design-md)). The corpus's Coinbase record, researched on 9 September 2026 rather than in the July window, shows a skill-driven eval passing 100% against 75.0% without the skill ([Coinbase CDS corpus record](https://cds.coinbase.com)).

A catalog-constrained environment on AG-UI moves the guarantee into the renderer, which refuses anything outside the catalog. The validator tells the agent what failed, and a review interrupt holds output until a person approves it. Because the output is data rather than arbitrary React, saving and diffing a prototype costs less. The table maps the recurring requirements against what exists ([A2UI Catalogs](https://a2ui.org/concepts/catalogs/); [A2UI v0.9.1 specification](https://a2ui.org/specification/v0.9.1-a2ui/); [AG2 docs](https://docs.ag2.ai/latest/docs/user-guide/ag-ui/a2ui); [Storybook MCP overview](https://storybook.js.org/docs/ai/mcp/overview); [Lovable design systems](https://docs.lovable.dev/features/design-systems); [Supernova prototyping contexts](https://learn.supernova.io/latest/portal/create/prototyping-contexts-jppeqv9d); [CopilotKit reference](https://docs.copilotkit.ai/reference); [Figma Help: Copy a Make preview](https://help.figma.com/hc/en-us/articles/35060759685015-Copy-a-Figma-Make-preview-as-design-layers); [UXPin Forge](https://www.uxpin.com/forge); [CopilotKit VS Code extension](https://docs.copilotkit.ai/angular/vs-code-extension); [Bolt](https://support.bolt.new/building/design-system/introduction)).

| Requirement | Exists today | Still open |
|---|---|---|
| Component contract | A2UI catalogs with `supportedCatalogIds` | Generating the catalog from the design system's own sources |
| Token binding | Lovable's raw-color detection; Supernova's locked contexts (corpus snapshot of 26–28 July 2026) | Declarative formats have a theme schema but no token model |
| Validation and repair | A2UI `VALIDATION_FAILED`; AG2 retry; Storybook's test loop (corpus snapshot of 26–28 July 2026) | Design-rule checks such as spacing and accessibility inside declarative formats |
| Human review | AG-UI interrupts; CopilotKit `useHumanInTheLoop` | Reviewing a generated surface with diff, approval and annotation |
| Round trip to Figma | Nothing; Make copies unlinked layers | Real library instances from generated UI |
| Save as code or stories | UXPin JSX export; CopilotKit catalog fixtures | Turning a generated surface into a story or pull request |
| Catalog versioning | A2UI's rules; Lovable and Bolt versions | Tying catalog versions to package semver |

In practice the environment is one agent endpoint with several clients. A Figma plugin serves designers, a Storybook addon serves developers and designers who work in code, and each client renders from the same catalog and exports to its own artifact. One protocol detail decides whether those clients can share work. AG-UI makes the client the keeper of the conversation. A producer "MUST treat [`messages`] as the complete history it is being shown", and `state` is "the consumer's last agreed value" ([Run Input](https://docs.ag-ui.com/spec/1.0/basic/run-input)). If a designer in a Figma plugin and a developer in Storybook work on one thread, each client sends its own copy of history and state. The protocol defines no shared thread store, so the environment needs one, keyed by the application-minted `threadId` ([The Event Model](https://docs.ag-ui.com/spec/1.0/basic/index)). The closest existing workbench is CopilotKit's VS Code extension, which previews catalog components from fixtures and streams AG-UI events into an inspector. It targets developers ([CopilotKit VS Code extension](https://docs.copilotkit.ai/angular/vs-code-extension)).

## Storybook 10.6 can host the endpoint and save the result as a story

Storybook's AI stack is official and in preview. `@storybook/addon-mcp` mounts an MCP server inside `storybook dev` at `/mcp`, and the docs warn "The API may change in future releases" ([Using Storybook with AI](https://storybook.js.org/docs/ai.md); [MCP server overview](https://storybook.js.org/docs/ai/mcp/overview.md)). The addon now ships from the core monorepo in lockstep with Storybook 10.6.1, published 29 September 2026 ([npm: @storybook/addon-mcp](https://registry.npmjs.org/@storybook/addon-mcp); [npm: storybook](https://registry.npmjs.org/storybook)). Storybook's benchmark on the Reshaped library reports "12.8% improved code usage", 2.76x faster runs and 27% fewer tokens ([Storybook MCP for React](https://storybook.js.org/blog/storybook-mcp-for-react/)). The corpus, a snapshot of 26–28 July 2026, counted 589 public GitHub hits for the addon in `main.ts` files ([State of AI Storybook record](https://state-of-ai-in-design-systems.netlify.app/platforms/storybook.md)).

Tool names changed after that snapshot. The corpus records `list-all-documentation`, `get-documentation`, `get-documentation-for-story`, `get-changed-stories`, `preview-stories` and `run-story-tests` ([State of AI Storybook record](https://state-of-ai-in-design-systems.netlify.app/platforms/storybook.md)). The newer 10.6 docs and 10.6.1 source use `docs-list`, `docs-show`, `docs-show-story`, `stories-changed`, `stories-preview`, `stories-find-by-component`, `review-create`, `test-run` and `get-storybook-story-instructions` ([MCP server overview](https://storybook.js.org/docs/ai/mcp/overview.md); [tool-names.ts](https://github.com/storybookjs/storybook/blob/v10.6.1/code/addons/mcp/src/tools/tool-names.ts)). The corpus also calls the docs toolset "React-only today", and 10.6 adds `angular-vite` and `vue3-vite` ([MCP server overview](https://storybook.js.org/docs/ai/mcp/overview.md)). No MCP tool writes a story. The agent writes the file itself after calling `get-storybook-story-instructions` ([MCP server overview](https://storybook.js.org/docs/ai/mcp/overview.md)).

The components manifest is the natural catalog source. `/manifests/components.json` lists each component's import statement, its props with types, descriptions and defaults, and rendered story snippets ([Manifests](https://storybook.js.org/docs/ai/manifests.md)). It is off by default and needs `features.componentsManifest: true`. The addon's older changelog says it defaults to on, but the newer 10.6.1 core preset and docs say off ([common-preset.ts](https://github.com/storybookjs/storybook/blob/v10.6.1/code/core/src/core-server/presets/common-preset.ts); [addon-mcp CHANGELOG](https://github.com/storybookjs/storybook/blob/v10.6.1/code/addons/mcp/CHANGELOG.md)). The manifest schema "is not yet stable and should not be considered a public API" ([Manifests](https://storybook.js.org/docs/ai/manifests.md)). An AG-UI backend can read it over HTTP from the same dev server and skip MCP, which avoids depending on tool names that just changed.

The dev server can host the AG-UI endpoint. It applies an `experimental_devServer` preset hook "to allow addons/frameworks to extend the dev server with middlewares" ([dev-server.ts](https://github.com/storybookjs/storybook/blob/v10.6.1/code/core/src/core-server/dev-server.ts)), and `@storybook/addon-mcp` mounts its whole MCP server that way ([addon-mcp preset.ts](https://github.com/storybookjs/storybook/blob/v10.6.1/code/addons/mcp/src/preset.ts)). A second hook, `experimental_serverChannel`, registers Node listeners on the dev server's WebSocket channel ([build-dev.ts](https://github.com/storybookjs/storybook/blob/v10.6.1/code/core/src/core-server/build-dev.ts)). The docs mention neither ([docs tree](https://github.com/storybookjs/storybook/tree/v10.6.1/docs)). During research, a throwaway 10.6.1 project mounted `POST /agui` through a local preset and streamed `RUN_STARTED` and `RUN_FINISHED` over SSE beside a working `/mcp` ([dev-server.ts](https://github.com/storybookjs/storybook/blob/v10.6.1/code/core/src/core-server/dev-server.ts)).

Storybook can also persist a generated screen. The Controls panel has saved args as a new story since 8.1 ([Storybook 8.1](https://storybook.js.org/blog/storybook-8-1/)). Underneath, the manager sends `saveStoryRequest` over the server channel. Node reads the CSF file, duplicates the source story under the new name with the new args, writes the file and waits for `STORY_RENDERED` ([save-story.ts](https://github.com/storybookjs/storybook/blob/v10.6.1/code/core/src/core-server/utils/save-story/save-story.ts); [core-events](https://github.com/storybookjs/storybook/blob/v10.6.1/code/core/src/core-events/index.ts)). It handles CSF 3 and CSF Next stories and rejects CSF 2 ([update-args-in-csf-file.ts](https://github.com/storybookjs/storybook/blob/v10.6.1/code/core/src/core-server/utils/save-story/update-args-in-csf-file.ts)). During research, a plain Node WebSocket client holding the channel token sent `saveStoryRequest` and appended `export const GeneratedFromAgent` with a nested JSON spec arg, and the new story appeared in the index within about two seconds ([get-server-channel.ts](https://github.com/storybookjs/storybook/blob/v10.6.1/code/core/src/core-server/utils/get-server-channel.ts); [save-story.ts](https://github.com/storybookjs/storybook/blob/v10.6.1/code/core/src/core-server/utils/save-story/save-story.ts)). These channel events are internal and exist only in dev. Storybook makes no stability promise for them, and the Storybook 11 alpha is already on npm's `next` tag ([npm: storybook](https://registry.npmjs.org/storybook)).

The combined design is a host story whose single `spec` arg holds a catalog tree, rendered by a component that maps the tree onto the design system. Saving writes a story made of data, with no generated JSX to lint. Small repositories already render json-render and A2UI specs inside stories from static data ([jaml-ui](https://github.com/OptimusPi/jaml-ui/blob/HEAD/src/json-render/stories/jsonRender.stories.tsx); [a2ui-demo](https://github.com/beldenschroeder/a2ui-demo/blob/HEAD/apps/storybook/src/stories/Button.stories.tsx); [elmethis](https://github.com/46ki75/elmethis/blob/HEAD/packages/react/src/components/a2ui/elm-a2ui.stories.tsx)). Southleft's Story UI takes the other route. It writes real `.stories.tsx` files from its own Express server, checks imports, props and tokens, renders in a browser with axe and a vision model, and can commit the story to a branch and open a pull request ([Story UI README](https://github.com/southleft/story-ui/blob/f960dda85257854c20fe13acc1e36c1ae3bf50de/README.md)). It streams progress over its own SSE events: `started`, `preview_ready`, `llm_text`, `intent`, `progress`, `validation`, `retry`, `completion` and `error` ([streamTypes.ts](https://github.com/southleft/story-ui/blob/f960dda85257854c20fe13acc1e36c1ae3bf50de/mcp-server/routes/streamTypes.ts)). Those map closely onto AG-UI's run lifecycle, text messages, steps and custom events, which makes Story UI the cheapest Southleft product to put behind an AG-UI adapter. GitHub code search found no `.storybook` configuration that imports `@ag-ui/client` ([GitHub code search](https://github.com/search?q=%22%40ag-ui%2Fclient%22+path%3A.storybook&type=code)). CopilotKit's own Storybook documents its chat components, not generated UI ([CopilotKit storybook](https://github.com/CopilotKit/CopilotKit/blob/main/examples/v2/react/storybook/package.json)).

A generated story can be checked with the tools Storybook already recommends to agents. `@storybook/addon-vitest` turns each story into a browser test, and `parameters.a11y.test: 'error'` fails the test on axe violations ([Vitest addon](https://storybook.js.org/docs/writing-tests/integrations/vitest-addon.md); [Accessibility tests](https://storybook.js.org/docs/writing-tests/accessibility-testing.md)). The `test-run` MCP tool appears only when addon-vitest is installed ([MCP server API](https://storybook.js.org/docs/ai/mcp/api.md)). Storybook's agentic setup tags new stories `ai-generated` for review ([Agentic setup](https://storybook.js.org/docs/ai/setup.md)). No official tool validates a JSON spec against the manifest before render, so the environment has to build that check.

## What the prototypes in this lab test

The research above leaves six hypotheses that only a working prototype can settle. The lab's README records what was built and what held.

| Hypothesis | Claim to confirm or refute |
|---|---|
| Catalog as tool schema | A design system's catalog, expressed as AG-UI frontend tools with JSON Schema parameters, keeps an agent to approved components and props. |
| Shared-state streaming of a UI tree | A UI tree carried in `STATE_SNAPSHOT` and `STATE_DELTA` renders progressively and carries a person's edits back to the agent on the next run. |
| Validate-and-repair loop | Validation against the catalog, reported back as tool errors, brings the agent to a valid tree within a bounded number of runs. |
| Interrupts for design review | An interrupt outcome and its `resume` answer can hold a generated surface until a person approves, rejects or edits it. |
| Export tools per surface | One validated tree can become each surface's native artifact, such as a Storybook story or Figma component instances. |
| Figma and Storybook as AG-UI clients | A Figma plugin and a Storybook addon can each run a conforming AG-UI client within their runtime limits. |

## Conclusion: publish the catalog first, then build the clients

The durable asset is the catalog and its validator. The transport matters less. One JSON Schema per component can serve as AG-UI tool parameters or as an A2UI catalog entry, and Chakra's MCP server already uses its live component list to make a nonexistent component fail schema validation ([schema.json](https://ag-ui.com/spec/1.0/schema.json); [A2UI Catalogs](https://a2ui.org/concepts/catalogs/); [Chakra MCP tools](https://raw.githubusercontent.com/chakra-ui/chakra-ui/HEAD/apps/mcp/src/tools/index.ts)). AG-UI itself promises that 0.x agents keep working against 1.0 clients ([Migrating to 1.0](https://docs.ag-ui.com/migrating-to-1-0)). The missing piece nobody owns is a component's identity across surfaces. Code Connect maps Figma props to code, Specs carries Figma node and variable IDs, and the Storybook manifest carries import paths ([Code Connect React](https://developers.figma.com/docs/code-connect/react/); [Schema: Metadata](https://www.specsplugin.com/schema/metadata/); [Manifests](https://storybook.js.org/docs/ai/manifests.md)). A catalog entry that holds all three keys is what lets one generated tree become both a story and a set of Figma instances. The field has a clear gap to fill. A2UI tells teams to mirror their design system ([A2UI Catalogs](https://a2ui.org/concepts/catalogs/)). Design system teams have spent 2026 building MCP servers and CLIs for coding agents instead ([Uber Base MCP](https://uber.design/base-mcp); [Atlassian ADS CLI](https://www.atlassian.com/blog/ai-at-work/giving-ai-agents-design-system-context-from-the-terminal-what-we-learned-building-a-cli)), and the corpus, a snapshot of 26–28 July 2026, records none that has published the bridge ([State of AI in Design Systems](https://state-of-ai-in-design-systems.netlify.app)).

The sequence below front-loads work that pays off with or without AG-UI and defers anything built on pre-1.0 or undocumented APIs.

| Order | Action | Adopt, build or wait | Why |
|---|---|---|---|
| 1 | Turn on `componentsManifest`. Generate one JSON Schema per component from the manifest and your TypeScript types. Publish it with the package under a `catalogId` URI and follow A2UI's add-only rules. | Adopt now | Every agent surface can consume it, and A2UI fixes catalogs at deploy time |
| 2 | Add cross-surface keys to each catalog entry: import path, Figma component key, and the Code Connect mapping where your Figma plan includes it. If your team runs Specs, merge its enums, slot rules, invalid combinations and roles, pinned to one schema version. | Adopt now | Every export path needs identity, and the Specs schema changes often |
| 3 | Build a validator that checks trees against the strict catalog and returns JSON Pointer errors. Give the model a flatter schema. | Build now | AG-UI validates nothing, and providers handle `oneOf` and `$ref` unevenly |
| 4 | Standardize new agent-facing UI on `@ag-ui/client` 1.0.x over HTTP and SSE. Prefix `CUSTOM` names and activity types with your own namespace, and carry extra data in `metadata`. | Adopt now | The 1.0 core is normative, and the client strips unknown fields |
| 5 | Build a dev-only Storybook addon: the agent endpoint, a host story that renders a `spec` arg, save-as-story, and addon-vitest with `a11y.test: 'error'` as the gate. Pin the Storybook version. | Build next | Same origin, no plugin distribution, and the test tooling already exists |
| 6 | Build the Figma plugin client in the UI iframe. Render validated trees as library instances, put canvas writes behind consent, tag the agent's edits, and add a shared server-side thread store. | Build after Storybook | This is the unbuilt part, and it depends on the keys from step 2 |
| 7 | Add an interrupt-based review gate to both clients, with approve-with-edits. | Build | Review of generated surfaces is still an open requirement |

Wait before depending on five things. Leave the A2UI middleware's key names (`a2ui-surface`, `a2ui_operations` and the context description) alone until `@ag-ui/a2ui-middleware` reaches 1.0, and treat A2UI 1.0 as a candidate until it is final ([npm @ag-ui/a2ui-middleware](https://registry.npmjs.org/@ag-ui/a2ui-middleware); [a2ui.org](https://a2ui.org/)). Treat Storybook's `experimental_devServer`, `experimental_serverChannel` and `saveStoryRequest` as unsupported and retest them on Storybook 11 ([docs tree](https://github.com/storybookjs/storybook/tree/v10.6.1/docs); [npm: storybook](https://registry.npmjs.org/storybook)). Wait for the Specs schema to reach 1.0 before calling it stable ([npm: specs-schema](https://registry.npmjs.org/@directededges%2Fspecs-schema)). Wait for Figma's official MCP server to offer events before building an event-driven loop on it ([Figma MCP server](https://developers.figma.com/docs/figma-mcp-server/)). Wait for AG-UI to specify capability retrieval and to settle its generative UI draft ([Capabilities 1.0](https://docs.ag-ui.com/spec/1.0/basic/capabilities); [Generative UI draft](https://docs.ag-ui.com/drafts/generative-ui)). Meanwhile, use Figma Console MCP's structured tools as the agent's Figma backend and keep `figma_execute`, which runs arbitrary JavaScript, out of the agent's reach ([tools.md](https://github.com/southleft/figma-console-mcp/blob/db1967f479514710acc64be4c527ac033410b772/docs/tools.md)). Keep MCP Apps to dashboards such as Figma Console MCP's token browser, because the open-ended lane cannot guarantee brand or accessibility ([CopilotKit Generative UI overview](https://docs.copilotkit.ai/concepts/generative-ui-overview)). Revisit this list when the A2UI middleware ships 1.0 or when Storybook documents its server hooks.
